# GoRide AI — responsive ride-booking MVP

**Tagline:** Your Ride. Your Price. Your Choice.

This is a runnable full-stack starter with a React + TypeScript PWA frontend, Express API, PostgreSQL schema, demo OTP login, transparent fare quotes, ride booking lifecycle, role-specific screens, fare audit, support, and admin/driver views.

## Important scope and safety notes
- The app defaults to **DEMO MODE**. Sample drivers, quotes, trips, OTPs, and payment outcomes are simulated and labelled in the UI. They are not real drivers, live locations, traffic, or payments.
- The OTP is `123456` in demo mode only. Do not use demo authentication in production.
- Production deployment requires a real SMS/OTP provider, maps/geocoding provider, payment gateway, secure session storage, document storage, monitoring, and legal/compliance review.
- Do not collect or store raw card details. Payment integration is intentionally a sandbox adapter placeholder.
- The PostgreSQL migration is included; the API currently uses an in-memory demo repository so it runs without credentials. `DATABASE_URL` and migration steps are provided for connecting a persistent repository.
- Driver document uploads are represented by a clearly labelled demo flow; no identity documents are uploaded or stored by this starter.
- Fare values are estimates and are fully itemized. The demo never prices based on phone model, battery percentage, or personal characteristics.

## Run locally
Requirements: Node.js 20+ and npm.

```bash
npm install
cp .env.example .env
npm run dev
```
Open `http://localhost:5173`.

## Android phone setup
The easiest route is to upload this ZIP to a GitHub repository using your browser, then open the repository in a cloud development environment (for example GitHub Codespaces, if available) or use a hosted IDE that supports Node.js. Install dependencies and run `npm run dev -- --host 0.0.0.0`; use the preview URL generated by that environment. Running a full Node/PostgreSQL stack directly on an Android phone is possible only with additional tooling and is not the beginner-friendly route.

## Scripts
- `npm run dev` — Vite frontend and Express API together
- `npm run build` — TypeScript check and frontend production build
- `npm run start:api` — API only
- `npm run db:migrate` — apply SQL migration to PostgreSQL using `DATABASE_URL`

## Environment
See `.env.example`. Never commit real API keys or secrets.

## API overview
- `GET /api/health`
- `GET /api/config`
- `POST /api/auth/request-otp`
- `POST /api/auth/verify-otp`
- `GET /api/rides`
- `POST /api/quotes`
- `POST /api/bookings`
- `PATCH /api/bookings/:id/status`
- `GET /api/driver/earnings`
- `GET /api/admin/analytics`
- `POST /api/fare-audit`
- `POST /api/support/tickets`

## Production hardening checklist
1. Replace demo OTP with provider-backed OTP and rate limits.
2. Replace in-memory repository with PostgreSQL repository and run migrations.
3. Add secure, HTTP-only, SameSite cookies or a vetted identity provider.
4. Add role authorization middleware to every protected endpoint.
5. Integrate Maps SDK/geocoding/directions and clearly disclose location permissions.
6. Integrate a payment provider's sandbox, then production mode after compliance checks.
7. Add real-time dispatch/WebSockets, driver location consent, and abuse controls.
8. Add encrypted private document storage and a verification vendor for drivers.
9. Add tests, observability, backups, privacy policy, terms, and regional transport compliance.
